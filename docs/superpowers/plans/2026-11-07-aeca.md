# AECA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build AECA, the Gmail and Calendar agent in the design, and hand it over on Sunday 2026-11-08 in the evening, with every scenario of the brief working live in Docker.

**Architecture:** Ports and adapters, as in ARDE.
- `domain` holds pure types and rules: the facts, the decision and its validator, the policy records, the planner and the approval states.
- `application` runs the inbox loop and the approval loop through ports: `Mailbox`, `Calendar`, `LLMClient`, `StateStore`, `AuditLog`, `Tracer`, `Clock` and `Lease`.
- `adapters` implement those ports for Gmail, Google Calendar, Anthropic, SQLite and the files on the volume.
- The model only returns a typed decision. Code decides every action, and every action happens exactly once.

**Tech Stack:**
- Python 3.12, uv, pydantic, pyyaml;
- google-api-python-client, google-auth and google-auth-oauthlib;
- the anthropic SDK;
- SQLite, from the standard library;
- pytest, ruff and mypy (strict);
- Docker Compose, Make and GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-05-aeca-design.md`, commit `151fcaf`. Executors read both. Where this plan is silent, the spec decides. Where the two conflict, the spec wins, unless the conflict is listed under Deviations.

**Time:** Saturday 2026-11-07 and Sunday 2026-11-08, until the handover in the evening.
- Tasks 1–12 are Saturday's, and Tasks 13–18 are Sunday's.
- If Saturday runs late, Task 12's rehearsal moves after Task 13. The approvals come before everything else on Sunday.

## Global Constraints

**Code and tests:**
- Python `>=3.12`. Dependencies are managed by uv and locked in `uv.lock`.
- `make check` runs `ruff check`, `ruff format --check`, `mypy --strict src`, and `pytest -m "not live and not eval"`. It must pass before every commit.
- **Layers:**
  - `aeca.domain` imports only the standard library and pydantic.
  - `aeca.application` imports `aeca.domain`, the standard library and pydantic.
  - Nothing in either imports `aeca.adapters`, `aeca.tools`, `googleapiclient`, `google` or `anthropic`.
  - `tests/test_architecture.py` enforces this from Task 5 onwards.
- **Ionel's rules:**
  - names reveal intent; functions are small;
  - more than two positional parameters become a dataclass;
  - comments say *why*, never *what*;
  - TDD, F.I.R.S.T.;
  - third-party libraries stay behind adapters.
- **Datetimes** are always timezone-aware. Code gets "now" only from the `Clock` port.
- **Opt-in tests:** a test that touches the network or costs money carries the `live` or `eval` marker, and `make check` never runs it.

**Gmail behaviour:**
- **Label names, exactly:**
  - `MEETING_REQUEST`, `TASK`, `INFO_ONLY`, `SALES_OUTREACH`, `MARKETING`, `URGENT`, `Finance`, `UNKNOWN`;
  - `AECA/processed`, `AECA/error`, `AECA/awaiting`.
- SPAM is Gmail's own `SPAM` system label.
- **Every Gmail change targets one message, never a thread.**
- **Replies go only to the original `From`**, never to `Reply-To`, and never to an address found in an email's text.
- **Every message AECA sends carries `X-AECA-Kind` and `X-AECA-Id`.** A reply also carries `Auto-Submitted: auto-replied`, `In-Reply-To`, `References` and the source `threadId`.
- **No line AECA writes starts with `APPROVE` or `REJECT`.**
- **Ids derive from the Gmail message id, never from a counter:** approval ids, event ids and action keys.

**The model:**
- Anthropic SDK with `max_retries=0`. The adapter retries 429s, 5xx errors and dropped connections itself, and traces every attempt.
- The model never reads an approval reply.

**Secrets:**
- No agent reads, prints, copies or sources `.env`. Only Make, Compose and `aeca auth` touch it.
- Secret values live in `SecretStr`. Every file AECA writes redacts them by exact match.
- Email bodies never go in `audit.jsonl`. `debug.log` is off by default.

**Git:**
- Stage files by path; never `git add .` or `-A`.
- One commit per task, ending with the attribution lines.
- Never push.

## Review Focus

These are the inputs most likely to break AECA for a real user that the spec doesn't spell out. Each has a test in the task named.

1. **A forged `Authentication-Results` header below Gmail's own, claiming `dmarc=pass`.** Only the topmost header whose authserv-id is `mx.google.com` counts. Otherwise a phisher passes as internal, or as the manager. (Task 3)
2. **Non-ASCII headers and bodies.** For example an RFC 2047 encoded `From` name and subject ("Jürgen Müller", "Änderung"), a `windows-1252` body, or an undecodable byte. Facts must decode them and replies must encode them, with no crash. The evaluators write from Germany. (Tasks 3 and 9)
3. **A proposed time in a different zone from the calendar**, such as "15:00 CET" against a Europe/Bucharest calendar. The planner compares aware datetimes, and the confirmation states the calendar's zone. (Task 10)
4. **An `INTERNAL_SENDERS` entry and a `From` that differ in case or form**, such as `Boss@Company.COM` and `"The Boss" <boss@company.com>`. The sender still counts as internal. (Task 3)
5. **An HTML-only newsletter whose links are images, or tracking redirects with no anchor text.** No link counts as mismatched, so the SPAM rule doesn't fire on an ordinary newsletter. (Task 3)

## Deviations

**From the spec:**
- **No test-email generator agent** (Ionel, 2026-11-07). Claude writes the corpus, and Ionel checks it. The cost: the corpus shares Claude's assumptions about what the evaluators will send. Ionel's check is the only independent view of it.
- **No `insert` mode and no scorer** (Ionel, 2026-11-07).
  - The cases that need a forged sender run only in `make eval` and the offline suite.
  - Results are checked by eye.
- **The onboarding page is written once,** at the end (Ionel, 2026-11-07).
- **`make auth` bind-mounts `.env` into a one-off container,** so the token can be written without being printed. That departs from "secrets come only from `env_file`". It applies only to the `auth` service, which doesn't run AECA. The fallback is to run it on the host with uv.
- **The rehearsal sends over SMTP with app passwords,** not the Gmail API (Claude). That saves an OAuth consent for each sender account. The cost: each sender account needs 2-Step Verification and an app password.

**From Ionel's conventions:**
- **The spike script** in `docs/research/spikes/` has no tests, and is excluded from ruff and mypy. It is throwaway evidence, as in ARDE.
- **`process_email.py` grows across Tasks 8 and 11.** Task 8's thin path is replaced, not kept beside the full one.
